# 破壳 (Pòké) — MVP 原型

> 把刷不完的群消息，变成今天值得做的 3 件事。
> Turn the endless stream of group messages into the 3 things worth doing today.

一个**单文件、零依赖**的手机端原型，用来验证一个核心假设：
**当信息被筛成「一小份、可行动」时，学生会不会真的去点、去做、去找搭子。**

## 怎么运行

直接**双击 `index.html`** 用浏览器打开即可。手机预览体验最佳：在浏览器里按 F12 → 切到手机视图（或直接发到自己手机上打开）。

数据存在浏览器 `localStorage`（仅本机），刷新不丢。

## 三个标签页

| 标签 | 解决你的哪条痛点 | 做什么 |
|---|---|---|
| **今天** | 信息过剩 + 聚合活动通知 + 信息茧房 | AI 风格筛过的「今日精选 3 件事」+ 1 张「破壳卡」（圈外内容）。每条可「想去 +1 / 找搭子」 |
| **我的** | 找搭子 | 你主动标记的事都在这，把信息变成行动 |
| **复盘** | 提升认知 / 健脑 | 对你真正「去过」的事，给一个 30 秒认知小问题，写两句即可 |

## 运营后台（右上角「运营」）

- 手动录入今天的条目（MVP 阶段先不用 AI，先验证需求）。
- 看 4 个关键指标：**想去点击 / 找搭子点击 / 真实到场 / 写了复盘**。
- 最该盯的一个数：**到场率**（「想去」很便宜，真去+复盘才证明需求是真的）。

## 怎么做真实验证（最重要）

原型本身只是工具。真正的 MVP 测试是：

1. 选**一个**范围（你自己的班 / 一个社团）。
2. 这一周你**手动**把活动/通知整理进「运营后台」。
3. 每天把这个页面发到群里。
4. 只看一个数：**有多少人真的点了「想去」，并且真的去了。**

人会行动 → 这个产品值得继续做（再考虑做真正的 AI agent + 后端共享计数）。
人不行动 → 是需求问题，先别写代码。

## 已知限制（刻意的）

- 计数、搭子是**本机模拟**的（演示用）。多人共享计数需要加一个简单后端（下一步）。
- 没有登录、没有真实数据源接入——这些都是验证通过**之后**才做的事。
